# AniMotion Studio 0.3 — Low VRAM Edition

Бесплатная локальная студия для подготовки анимационных сцен, раскадровки и персонажей. Проект постепенно подключает локальные модели; он не требует платной подписки или обязательного облачного API.

> **Профиль компьютера:** NVIDIA GeForce RTX 2050, 4 ГБ выделенной видеопамяти. По снимку диспетчера задач также видно 15,7 ГБ системной RAM, из которых в тот момент было занято 13,4 ГБ. Поэтому тяжёлую генерацию видео не считаем совместимой без отдельной проверки.

## Запуск на Windows

1. Установи Python 3.10 или новее с https://www.python.org/downloads/ и включи `Add Python to PATH`.
2. Скачай репозиторий через GitHub Desktop или Code → Download ZIP и распакуй его.
3. Дважды щёлкни `CHECK-GPU.bat`, чтобы увидеть адаптер и объём VRAM.
4. Дважды щёлкни `start-animotion.bat`.
5. Открой http://127.0.0.1:8090 (страница обычно откроется сама). Не закрывай чёрное окно, пока пользуешься приложением.
6. Для остановки нажми `Ctrl+C` в чёрном окне.

AniMotion web-сервер и его прокси слушают только `127.0.0.1` — они не публикуются в локальную сеть или интернет.

## Что делать на RTX 2050 4 ГБ

**Не начинай с Wan 2.2, Stable Video Diffusion или больших text-to-video workflow.** У них слишком высокий риск нехватки видеопамяти на 4 ГБ.

Рекомендуемый порядок:

1. **Сначала — монтажная анимация из готовых изображений.** Панорамы, медленные наезды/отъезды, титры, смена планов, слои и эффекты. Это намного легче для GPU, чем диффузионная генерация видео.
2. **Для одиночных изображений — Stable Diffusion 1.5 как эксперимент.** Начинай с 384×384, batch 1, FP16 и low-VRAM/offloading, если workflow это поддерживает. 4 ГБ — тесный запас; успех и скорость не гарантируются.
3. **Для анимации портретов — LivePortrait как отдельный эксперимент.** Он переносит движение/мимику с driving-видео на исходное изображение лица. Он не превращает произвольный текст в полноценное видео и не анимирует любые объекты. Сначала делаем короткий тест; фактическая потребность в VRAM зависит от окружения и настроек.
4. **AnimateDiff не ставим по умолчанию.** Опубликованные оптимизированные замеры для SD 1.5 показывают около 4,21–5,60 ГБ VRAM в одной конфигурации 512×512 и 16 кадров. Это не измерение на RTX 2050, но уже больше доступных 4 ГБ.
5. **Wan / SVD** не используем как первый шаг на этой видеокарте.

ComfyUI: https://github.com/Comfy-Org/ComfyUI  
LivePortrait: https://github.com/KwaiVGI/LivePortrait  
Замеры AnimateDiff: https://github.com/continue-revolution/sd-webui-animatediff/blob/master/docs/performance.md

## Подключение ComfyUI к AniMotion

1. Запусти ComfyUI локально на стандартном http://127.0.0.1:8188.
2. В AniMotion оставь адрес `/comfy` и нажми «Проверить подключение».
3. Загрузи совместимый API-workflow через раздел «Загрузить API-workflow (.json)».
4. В ComfyUI включи Dev Mode и выбери `File → Export Workflow (API)`. Обычный визуальный workflow JSON не подходит.
5. Выбери положительный и отрицательный текстовые узлы и только после этого запускай лёгкий workflow.

Не открывай порт 8188 в интернет. Не загружай неизвестные workflow без проверки их узлов и загрузок.

## Известные ограничения

- AniMotion — ранний прототип редактора и отправки workflow в ComfyUI. Наличие кнопки генерации не гарантирует, что любой workflow совместим.
- LivePortrait указан как кандидат для отдельного теста; автоматическое управление LivePortrait из интерфейса пока не подключено.
- Stable Diffusion 1.5 — модель для картинок, не видеогенератор.
- Сцены и параметры хранятся в localStorage браузера на текущем устройстве. Делай экспорт проекта JSON для резервной копии.
- Не добавляй в GitHub веса моделей, большие видео, ключи, пароли или файлы `.env`.

## Разработка

Проверки проекта:

```bash
python -m unittest discover -s tests -v
python -m py_compile run_server.py
```

## Структура

- `index.html` — интерфейс студии.
- `run_server.py` — локальный веб-сервер и прокси ComfyUI.
- `start-animotion.bat` — запуск на Windows.
- `CHECK-GPU.bat` — диагностика NVIDIA GPU.
- `docs/HARDWARE.md` — рекомендации по оборудованию.

## Безопасность и приватность

Репозиторий рекомендуется держать **Private**. В нём храним исходники и инструкции, но не веса моделей, личные видео, пароли, API-токены или файлы `.env`. Локальный сервер доступен только с этого компьютера.
